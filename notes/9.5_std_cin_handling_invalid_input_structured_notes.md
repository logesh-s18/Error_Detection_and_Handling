# 9.5 — `std::cin` and Handling Invalid Input

---

## 🧭 Project Logic Overview

> **Mental Model:** Console input becomes available in the standard input stream. `std::cin` later extracts that input according to the operation being used.

```text
                         INPUT STREAM
                              │
                              ▼
                    '1'  '2'  '3'  '\n'
                              │
                 ┌────────────┴────────────┐
                 │                         │
          FORMATTED EXTRACTION      UNFORMATTED EXTRACTION
                 │                         │
              `cin >>`                  `get()`
                 │                         │
          "Interpret as a type"       "Take character"
                 │                         │
                 ▼                         ▼
                123                       '1'
```

### Formatted vs Unformatted

| Operation | Style | Whitespace | Mental Model |
|---|---|---|---|
| `std::cin >> value` | Formatted | Usually skips leading whitespace | **Interpret input as a type** |
| `std::cin.get(ch)` | Unformatted | Does not skip whitespace | **Take current character** |
| `std::getline()` | Line-oriented | Does not skip leading whitespace | **Take the line** |
| `std::ws` | Manipulator | Consumes leading whitespace | **Clean whitespace from the front** |
| `std::cin.peek()` | Look-ahead | Does not skip whitespace | **Look, don't consume** |

---

# 🧠 Important `std::cin` Operations

### `std::cin >>`

```cpp
std::cin >> value;
```

* Performs **formatted extraction**.
* Usually skips leading whitespace.
* Interprets characters according to the requested type.
* Consumes the characters that form the extracted value.

**ROT:** `>>` → **Skip leading whitespace → interpret → extract.**

---

### `std::getline()`

```cpp
std::getline(std::cin, str);
```

* Extracts characters until it reaches a newline.
* Stores them as one complete line in a `std::string`.
* Consumes the delimiter newline.

**ROT:** `getline()` → **Extract the line until `\n`.**

---

### `std::ws`

```cpp
std::cin >> std::ws;
```

* Consumes and discards leading whitespace.
* This includes spaces, tabs, and newlines at the current front of the stream.

**ROT:** `std::ws` → **Discard leading whitespace from the front.**

---

### `std::cin.get()`

```cpp
char ch{};
std::cin.get(ch);
```

* Performs character-level extraction.
* Takes the character currently at the input position.
* Advances the current extraction position.
* Does **not** skip whitespace.

**ROT:** `get()` → **Take current character → move forward one position.**

---

### `std::cin.peek()`

```cpp
char ch = std::cin.peek();
```

* Looks at the character currently at the input position.
* Does not consume it.
* Does not advance the current extraction position.
* Can see whitespace such as `' '`.

**ROT:** `peek()` → **Look at the current character without consuming it.**

```text
A   B   C   D
↑
└── peek(): looks here, position stays here
```

---

### `std::cin.putback()`

```cpp
std::cin.putback('X');
```

* Adjusts the input sequence so the supplied character becomes available before the character that was previously next to be extracted.
* It does **not** mean "replace the current character".
* It makes the supplied character available as the next character.

```text
Before:

B   C   D
↑
next extraction

putback('X')

After:

X   C   D
↑
X is now next
```

**ROT:** `putback(c)` → **Make `c` available before the previously-next character.**

---

# ⚠️ Whitespace: The Important Trap

### `cin >>` vs `peek()`

`operator>>` skips whitespace **when that formatted extraction begins**. It does not remove every whitespace character from the stream forever.

Example:

```cpp
int x{};
std::cin >> x;
```

Input:

```text
25 abc
```

After extracting `25`:

```text
25··abc\n
  ↑
current extraction position
```

The space can remain.

```cpp
char ch = std::cin.peek();
```

can therefore produce:

```text
ch == ' '
```

because `peek()` observes the exact next character and does not skip it.

**ROT:** `>>` may skip leading whitespace for its own extraction; `peek()` sees whatever character is currently at the front, including a space.

---

# 🧪 Trailing Space Character

### Q: What real-time problem can happen if a user enters `25` followed by spaces and presses Enter?

**A:** The program may ask the user to enter another value because the spaces after `25` are still treated as input characters, making the user confused as the console looks blank after `25` even though the program is waiting for another input.

```text
25····⏎
  ↑
trailing spaces
```

After `25` is extracted:

```cpp
!std::cin.eof()         → true    // EOF illa
std::cin.peek() != '\n' → true    // ' ' != '\n'

true && true → true
```

### Important distinction

```text
Unextracted character
        ≠
Meaningful value
```

A space is an actual character, but it is not necessarily a meaningful value for the program.

# 🔍 `hasUnExtractedInputs()` — Boolean Logic

```cpp
bool hasUnExtractedInputs()
{
    return !std::cin.eof() && std::cin.peek() != '\n';
}
```

> **It is a single-time check of the single character currently pointed to by the input stream's current extraction position.**

It does not continuously monitor the stream.

```text
Call function
     │
     ▼
Check current position
     │
     ▼
Check EOF state
     │
     ▼
peek() current character
     │
     ▼
Return true / false
```

If you call it again after extraction has moved the position, it performs a **new check at the new position**.

---

# 📊 Complete Boolean Logic Table

| `!eof()` | `peek() != '\n'` | Result | Meaning |
|:---:|:---:|:---:|---|
| `true` | `true` | **`true`** | Input innum mudiyala + next char `\n` illa → current line-la unextracted character irukku ✅ |
| `true` | `false` | **`false`** | Input innum mudiyala + next char `\n` → current line mudinjiduchu ❌ |
| `false` | `true` | **`false`** | EOF reached → input source-la inime normal input character illa ❌ |
| `false` | `false` | **`false`** | EOF reached → input source-la inime normal input character illa ❌ |

### `true && true`

* `!eof()` → `true` = **input innum mudiyala.**
* `peek() != '\n'` → `true` = **next character `\n` illa.**
* `true && true` → **`true`**.
* Function result `true` → **current line-la innum unextracted character irukku.** ✅

### `true && false`

* `!eof()` → `true` = **input innum mudiyala.**
* `peek() != '\n'` → `false` = **next character `\n` ah irukku.**
* `true && false` → **`false`**.
* Function result `false` → **current line-la innum character illa before newline.** ❌

### `false && true`

* `!eof()` → `false` = **input source EOF reached.**
* `peek() != '\n'` → not a normal character-level state to rely on after EOF.
* `false && true` → **`false`**.
* Function result `false` → **input source-la inime normal input character illa.** ❌

> **Important:** Genuine EOF-la `peek()` does not provide a normal input character. So `false && true` is mainly a logical combination, not a normal buffer state to construct.

### `false && false`

* `!eof()` → `false` = **input source EOF reached.**
* `peek() != '\n'` → not a normal meaningful character check after EOF.
* `false && false` → **`false`**.
* Function result `false` → **input source-la inime normal input character illa.** ❌

# 🧠 EOF vs `'
'`

```text
'\n'  → an actual newline character
EOF   → no more input is available
```

Think:

```text
'2' → '5' → '\n' → EOF
             ↑       ↑
          character  no more characters
```

> **`'\n'` is an actual character in the input stream; EOF means there are no more characters available.**

### Important EOF Nuance

> **`std::cin.eof()` does not mean "the next character is EOF". EOF is not a character. The EOF state is associated with the stream when an input operation reaches the end of the available input.**

---

# ⌨️ Enter Key vs Typing `\n`

Pressing Enter causes a **newline / line-ending character** to become part of the input stream.

```text
25 + Enter
      ↓
'2'   '5'   '\n'
             ↑
       newline character
```

Typing:

```text
\n
```

does **not** create a newline character. The stream receives:

```text
'\'   'n'
```

Typing:

```text
'\n'
```

also does not create a newline character. The quotes and backslash are simply typed characters.

**ROT:** `'
'` in C++ source code represents a newline character; typing `'
'` literally in the console does not create a newline. Pressing Enter does.

# 🧹 `clear()` vs `ignore()`

```text
                 std::cin
                    │
          ┌─────────┴─────────┐
          │                   │
      stream state        input buffer
          │                   │
       clear()              ignore()
          │                   │
     reset flags          discard chars
```

```cpp
std::cin.clear();       // reset error state
std::cin.ignore(...);  // remove unwanted input
```

**ROT:** `clear()` fixes the stream's state; `ignore()` cleans unwanted characters from the input stream.

# 🚦 Stream State Flags

| Flag | Meaning |
|---|---|
| `goodbit` | Stream is in a good state |
| `eofbit` | End of input has been encountered |
| `failbit` | Extraction/formatting failed |
| `badbit` | Serious I/O error occurred |

# 🧩 Input Validation Classifications

### 1. Inline validation

Prevent invalid input while it is being entered.

### 2. Post-entry validation with `std::string`

Let the user enter text, validate it, then convert it.

### 3. Validation through `std::cin`

Let `std::cin` and `operator>>` attempt extraction and handle failure.

---

# 🚨 Four Types of Invalid Text Input

* **1. Extraction succeeds, but the value is meaningless.**  
  Example: entering `k` as a mathematical operator.

* **2. Extraction succeeds, but extra input remains.**  
  Example: entering `*q hello` when only `*` was expected.

* **3. Extraction fails.**  
  Example: entering `abc` when a numeric value is expected.

* **4. Numeric overflow.**  
  The value cannot be represented by the target numeric type.

# ⚠️ Common Pitfalls / Gotchas

* `peek()` sees whitespace. It does not skip it.
* `get()` consumes whitespace too.
* `getline()` stops at `'
'`.
* `std::ws` removes leading whitespace.
* `operator>>` skips leading whitespace for formatted extraction.
* Trailing spaces can remain after successful formatted extraction.
* `peek() != '
'` does **not** guarantee a meaningful value exists.
* EOF is not a character.
* Do not imagine EOF as a special character sitting after `'
'`.
* `eof()` is a stream-state query, not a character peek.
* `clear()` changes stream state; it does not remove bad characters.
* `ignore()` removes characters; it does not reset stream state.

# 🎯 Interview Q&A

### Q: Does `std::cin >>` discard all whitespace?

**A:** No. Formatted extraction skips leading whitespace when that extraction begins. Whitespace after the extracted value can remain in the input stream.

### Q: Can `std::cin.peek()` see a space?

**A:** Yes. `peek()` does not skip whitespace. It observes the exact next character.

### Q: Does `peek()` consume the character?

**A:** No. It only looks at the current character and leaves the extraction position unchanged.

### Q: Does `get()` skip whitespace?

**A:** No. `get()` performs character-level extraction and can consume spaces, tabs, and newlines.

### Q: Is `'
'` the same as EOF?

**A:** No. `'
'` is an actual newline character. EOF means no more input is available.

### Q: What happens if the user types `\n` in the console?

**A:** It is treated as two ordinary characters, `'\'` and `'n'`. It is not interpreted as a newline escape sequence.

### Q: What happens if the user enters `25` followed by spaces and presses Enter?

**A:** A space may remain at the current input position after `25` is extracted, so `peek() != '
'` can return `true` even though there is no meaningful value left.

# ⭐ Key Takeaways

* **Input typed into the console becomes available in the standard input stream.**
* **`std::cin >>` performs formatted extraction.**
* **`get()` performs character-level extraction.**
* **`getline()` extracts a complete line.**
* **`std::ws` removes leading whitespace.**
* **`peek()` looks without consuming.**
* **`putback(c)` makes `c` available before the previously-next character.**
* **Spaces are actual characters in the input stream.**
* **`'
'` is an actual newline character.**
* **EOF is a stream condition, not a character.**
* **`clear()` resets stream error state.**
* **`ignore()` removes unwanted characters.**
* **A character being present does not necessarily mean a meaningful value is present.**
